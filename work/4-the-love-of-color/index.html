A painting contractor's site, rebuilt to be found.

A painting company's website with clear service pages, real project photos and an estimate request, backed by checks for all 29 searchable pages.

The situation

For this rebuild, the focus was helping someone understand the painting services, see examples of the work and request an estimate. The old Wix site still serves its original domain while the rebuilt site is live at 4theloveofcolor.com; completing that domain move is a separate part of the work.

The previous site described several services together, making it harder for visitors to find the detail relevant to their project. The rebuild gives interior, exterior and commercial painting their own pages, with cabinet refinishing retained as a secondary offer. Separate pages make the scope clearer; they do not, by themselves, establish a ranking improvement.

What was done

  1. One route table, as data

    Page addresses, titles, descriptions and sharing images are defined in the route data. The build and sitemap use those definitions, and an automated check catches missing or unexpected pages before publication.

  2. A real HTML file per route

    Each page's text, title, description and preferred URL are included in the HTML served by the site. Visitors and crawlers can read the main content without waiting for the interactive parts of the page to start.

  3. A page per service, and per city that earned one

    The current site has seven service pages, four city pages and six pages explaining a particular service in a particular area. Each should help the visitor understand relevant work and link to the next useful page. There is no text-overlap percentage that guarantees indexing or rankings.

  4. Structured data that references rather than repeats

    One HousePainter entity declared once with an @id, and every Service and Breadcrumb node on every page points at it instead of restating the business. One place to change a phone number.

  5. An automated gate wired into the build

    Titles, descriptions, canonicals, h1 counts, image alt text, JSON-LD validity, sitemap coverage in both directions, orphan pages, and internal links that don't resolve — all checked on every build, which fails if anything regresses.

  6. Images cut to what a phone needs

    Responsive variants generated at build time so a phone downloads a phone-sized photo, with explicit dimensions on every image to stop the layout jumping as they load.
