What's included

  • A written description of the users, workflow and first version
  • Web applications such as customer portals, dashboards and internal tools
  • Connections between existing systems where their supported integrations allow it
  • Access roles and a clear decision about who can view or change information
  • Tests based on the agreed workflow, including missing inputs and failures
  • A working preview for review before launch
  • Source-code handoff, setup notes and agreed account ownership
  • A separate estimate for hosting, subscriptions, maintenance and future changes

How the work goes

  1. Describe the job, not just the screen

    Tell us who does the work, what they enter, where it goes and what is difficult today. A useful starting brief is: customers submit a request, the office assigns it, and the team updates its status.

  2. Choose the smallest useful version

    We agree which users and actions belong in the first release. If an existing booking or business tool meets the need, configuration or a small integration may be a better use of the budget than rebuilding it.

  3. Build a preview and test the full journey

    The review covers more than appearance. We test the agreed user permissions, data changes, error handling and the path from the first request to the finished task. You review the workflow using representative examples.

  4. Launch with a plan for running it

    We document accounts, deployment, backups where needed and how changes will be handled. Support for a custom application is scoped for that system; it is not included in the $75 static-website care plan.

What people usually arrive with

“We keep copying information between tools”

An integration can move an approved request from one supported system to another, with a record of success or failure. The quote depends on the systems, access and what must happen when a transfer fails.

“Customers keep asking for the same status update”

A portal can give customers a view of their own project and documents. We first define what each person can see and which system is the source of the status.

“Our spreadsheet no longer fits the workflow”

A small internal application may make assignment, validation and reporting easier. We can start with one workflow and preserve an export path for your records.

Common questions

How much does custom software cost?

It is quoted after the workflow, users, integrations and acceptance criteria are defined. The $350, $750 and $1,500 website packages do not include a custom application. Any paid discovery or prototype stage is agreed before it begins.

Can you work with the tools we already use?

We first check the products, account access and supported integration options. We confirm feasibility before promising a connection, and identify any additional subscription or usage charges.

Do you build phone apps?

The focus of this offer is web applications that work in a browser, including on phones. App-store applications need a separate feasibility discussion and quote.

What should I send for a quote?

Describe one task, who uses the tool, what systems are involved and what a successful result would look like. Example data with private information removed is useful for initial scoping.
